EXECUTION FLOW
═════════════════════════════════════════════════════════════════════════════

1. EXTENSION LOAD
   manifest.json → Chrome registers extension
       ├─ Service worker (background.js) starts
       ├─ Content script (content.js) injected into all tabs
       └─ Extension icon appears in toolbar

2. USER SELECTS TEXT
   content.js → Detects selection via mouseup/selectionchange
       ├─ Gets selection bounds via getBoundingClientRect()
       ├─ Creates floating button element
       ├─ Positions button near selection
       └─ Shows button with opacity fade-in

3. USER CLICKS BUTTON
   content.js → Button click handler triggered
       ├─ Stores selected text in sessionStorage
       ├─ Sends message to background
       └─ Popup window opens

4. POPUP OPENS
   popup.html/popup.js → Initialized
       ├─ Reads selected text from sessionStorage
       ├─ Shows text preview
       └─ Waits for user to click "Summarize"

5. USER CLICKS SUMMARIZE
   popup.js → Sends SUMMARIZE message to background.js
       └─ return true (keep channel open for async responses)

6. BACKGROUND PROCESSES
   background.js → Message handler triggered
       ├─ Check if engine initialized
       │   ├─ If not: initializeEngine()
       │   │   ├─ Create MLCEngine instance
       │   │   ├─ Load model from HuggingFace (first time)
       │   │   │   └─ Cache in IndexedDB
       │   │   └─ Send progress updates to popup
       │   │
       │   └─ If yes: Reuse existing engine
       │
       ├─ Check text length
       │   ├─ If small: Direct summarization
       │   └─ If large: Chunk and summarize
       │
       ├─ Create streaming completion via WebLLM
       │   ├─ System prompt: Summarization assistant
       │   ├─ User prompt: Summary instructions + text
       │   └─ Parameters: temperature=0.7, max_tokens=1000
       │
       ├─ For each token from stream:
       │   └─ Send TOKEN message to popup
       │
       └─ On completion:
           └─ Send COMPLETE message

7. POPUP UPDATES
   popup.js → Message handler receives responses
       ├─ TOKEN → Append to summary display (live update)
       ├─ STATUS → Show progress message
       ├─ INIT_PROGRESS → Show model download progress
       ├─ COMPLETE → Enable copy/new buttons
       └─ ERROR → Show error banner

8. USER ACTIONS
   popup.js → User interactions
       ├─ Click "Copy" → navigator.clipboard.writeText()
       ├─ Click "New Summary" → Reset UI for new text
       └─ Click "Close" → Close popup

9. CLEANUP
   popup.js → On close
       ├─ Clear summary text
       ├─ Clear selected text from sessionStorage
       └─ Engine stays loaded in background for next use

═════════════════════════════════════════════════════════════════════════════

✅ Content Security Policy (default Manifest V3)
✅ textContent used (not innerHTML) - prevents XSS
✅ Message validation - type checks on IPC
✅ No eval/Function - no dynamic code execution
✅ HTTPS only - model download over secure connection
✅ Sandboxed context - content script isolated
✅ No background permissions - can't access user browsing directly


PERFORMANCE OPTIMIZATIONS
═════════════════════════════════════════════════════════════════════════════

1. Singleton Engine Pattern
   ✓ Initialize model once
   ✓ Reuse across requests
   ✓ Avoid repeated initialization overhead

2. Lazy Model Loading
   ✓ Download only on first use
   ✓ Cache in IndexedDB
   ✓ Instant subsequent runs

3. Streaming Output
   ✓ Progressive token rendering
   ✓ No wait for full completion
   ✓ Better perceived performance

4. Simple Chunking
   ✓ O(n) complexity
   ✓ Paragraph-boundary aware
   ✓ Minimal overhead

5. IndexedDB Caching
   ✓ Automatic persistence
   ✓ No re-download on update
   ✓ Cross-session reuse

6. Message Batching (potential)
   ✓ Single message per token (already optimized)
   ✓ Consider batching multiple tokens in future
